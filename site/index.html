How it works

Keep it once. Bind per project. Run through Secretariat.

  1. Keep it once

    Capture it, add it in the guided item dialog, or import an existing .env without reading it. A whole folder tree can be imported at once, with a review list before anything is saved. Your Macs sync through iCloud keychain.

    secretariat import .env \
  STRIPE_SECRET_KEY \
  OPENAI_API_KEY \
  --profile acme-shop

  2. Your agent wires the project

    A profile maps environment variables to items for one folder. Agents create and bind profiles themselves, using names only. In Claude Code, each session learns at start which profile belongs to the folder.

    secretariat profile create \
  acme-shop --dir .
secretariat profile bind \
  acme-shop STRIPE_SECRET_KEY \
  acme/stripe/api/api_key

  3. Run through Secretariat

    The program gets the values as environment variables. Key files arrive as temporary files with mode 0600. The agent sees the program's output, with known values masked.

    secretariat run acme-shop \
  -- pnpm dev

Capture

A new key is on screen. Two seconds later it's safe.

Keys appear in a dashboard once, in a setup wizard, in a chat. Secretariat catches them where they show up, so they never land in a notes file or a stray .env first.

Clipboard inbox

Copy a key, press ⌃⌥⌘V. It goes to the Inbox with date and time, and the clipboard is cleared. No program gets it until you turn it into an item; the provider is guessed from the key's prefix.

Encrypted screenshots New

Recovery codes, a setup page, a QR code: paste the screenshot with ⌘V and add a note. Image and note are sealed with AES-GCM, synced through your private iCloud Drive container, and stay blurred until you click Show. No CLI or agent can open them.

From screenshot to item, on-device New

“Create Item …” reads the screenshot with Apple's text recognition and Apple Intelligence on your Mac, picks kind, provider and fields, and opens the item ready to check. Nothing leaves your Mac. Every value must appear in the screenshot, and look-alike characters are marked for you to compare.

Reading a screenshot with Apple Intelligence needs macOS 26 and a Mac that supports it. Without it, Secretariat uses text recognition and known key prefixes, and says so in the dialog.

Agent Guard

Before, during and after. In one tool.

Each layer covers a different way a key escapes: an agent reading it, a program printing it, a commit carrying it, or a leak that already happened years ago.

Output masking

When output goes to an agent or a pipe, every value the program received becomes [masked path/field] in stdout and stderr. In your own terminal you see the real output.

Touch ID per item

Mark an item and every run, push or inject that needs it waits for your fingerprint. Agents can switch approval on. Only you, in the app, can switch it off.

Commit guard

A git pre-commit hook refuses any commit that contains a value Secretariat knows. Your actual values, not patterns. Install it in every repository at once:

secretariat guard install \
  --all ~/work

Agent guard for Claude Code

A hook refuses cat .env, printenv, docker compose config and reading keychain passwords before they run, and tells the agent to use secretariat run instead.

secretariat guard claude install

Leak sweep, backwards in time

Checks every repository and its whole git history for your actual values, and names each key that was ever committed, with the commit. Those are the ones to rotate.

secretariat sweep ~/work

Retire your .env files

Once every value of a .env is in Secretariat, it goes to the Trash and a .env.example keeps the names. Files with anything unknown stay put.

secretariat tidy ~/work --apply

MCP tokens

Connect an MCP server. Nobody ever sees its token.

Remote MCP servers want a personal bearer token, and the usual setup guide says: paste it into a command. From then on it sits in plain text in your Claude Code config and your shell history. Secretariat hands it over at every connection instead.

The copy-paste way

claude mcp add --transport http \
  ideas https://example.app/mcp \
  --header "Authorization: Bearer tid_…"
  • The token is in plain text in ~/.claude.json and in your shell history.
  • Whoever pasted it has seen it, and so has any chat it passed through.
  • Paste the placeholder from the guide by mistake and the server just stops working.

Through Secretariat New

claude mcp add-json --scope user ideas '{
  "type": "http",
  "url": "https://example.app/mcp",
  "headersHelper":
    "secretariat header acme/ideas/token --bearer"
}'
  • Claude Code asks Secretariat at every connection. Its config holds a command, not a token.
  • The token goes from your keychain to the MCP client, never to the model. secretariat header refuses a terminal, and the agent guard refuses it as an agent command.
  • Rotate the item and the next connection uses the new token. Registered once, it works in every project.

Better still, create the token where it's issued: a script on the server generates it, passes it to secretariat import and deletes the temporary file. You never see it, your agent never sees it, and it's never lost. That's how our own MCP tokens are set up.

FAQ

Questions

Why isn't it in the Mac App Store?

App Store apps must run in a sandbox, and every program they start inherits that sandbox. secretariat run -- wrangler deploy couldn't run your tools or read your project folders. So Secretariat ships as a notarized Developer ID app instead.

Where are my keys, and what leaves my Mac?

Values live in your iCloud keychain. Syncing between your Macs is Apple's iCloud keychain, under your Apple Account. Secretariat itself has no server and sends no data anywhere: no telemetry, no account.

Does reading a screenshot send it anywhere?

No. Text recognition (Apple's Vision framework) and the language model (Apple Intelligence, on-device) both run on your Mac. Secretariat uses no cloud model and no network for it. Recognized text and suggested values stay in memory until you save the item, and nothing is logged.

What happens if I stop paying?

Nothing. It's a one-time purchase, not a subscription. The app keeps working, and your keys stay in your keychain.

Linux or Windows?

The app and CLI run on macOS 14 and later. Linux servers are supported as targets: Secretariat can push values to an env file over ssh. There is no Windows support.

Which agents does it work with?

Any agent that can run a shell command can use secretariat run. Claude Code also gets the session hint and the company rule file. Claude Desktop, Cursor and other MCP clients without a shell use secretariat mcp.

Is it open source?

Not yet: the code lives in a private repository for now. What you buy is the license for the signed, notarized build and its updates. The threat model describes how each protection works.

Does it stop a malicious agent?

Not by itself. It prevents accidental leaks. Against an agent that actively tries, your boundary is Touch ID approval per item. Details in the threat model.
