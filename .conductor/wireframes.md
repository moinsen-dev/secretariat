## 5. State Diagrams

### 5.1 Vault State Machine

```
┌──────────────────────────────────────────────────────────────────────────┐
│                        VAULT STATE MACHINE                               │
└──────────────────────────────────────────────────────────────────────────┘

                              ┌─────────────────┐
                              │                 │
               ┌──────────────│   UNINITIALIZED │
               │              │                 │
               │              └────────┬────────┘
               │                       │
               │              vault.init(password)
               │                       │
               ▼                       ▼
        ┌─────────────┐        ┌─────────────┐
        │             │        │             │
        │   LOCKED    │◄───────│  UNLOCKED   │
        │             │        │             │
        └──────┬──────┘        └──────┬──────┘
               │                       │
    unlock(password)            lock()
    unlock(touchID)           auto-lock (sleep)
               │               timeout
               │                       │
               └───────────────────────┘

  States:
  ┌──────────────────┐
  │ UNINITIALIZED    │ → No vault exists, show onboarding
  ├──────────────────┤
  │ LOCKED           │ → Vault exists but master key not in memory
  │                  │   • Show unlock dialog
  │                  │   • Secrets not accessible
  ├──────────────────┤
  │ UNLOCKED         │ → Master key in memory
  │                  │   • Full app functionality
  │                  │   • SDK can access secrets
  └──────────────────┘

  Transitions:
  ┌──────────────────┐
  │ vault.init       │ → Create vault with password
  │ unlock           │ → Derive key from password, store in memory
  │ lock             │ → Clear master key from memory
  │ auto-lock        │ → System sleep or idle timeout
  └──────────────────┘
```
